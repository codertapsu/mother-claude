# Languages of the interface

Mother Claude's interface speaks **English** (the default) and **Vietnamese**.
Each device chooses its own in **Settings › Appearance › Language**: the
desktop app and a paired phone may differ. The choice is kept in the
device's local storage and switches the whole interface at once.

What is not translated: messages the desktop's server composes (an error's
sentence from the Rust side, the admission and routing reasons on Capacity,
the decision rows in a conversation), push notifications, the browser
extension, names (Mother Claude, Claude, Claude Code, MCP, tmux, ngrok…),
commands, paths, code, and whatever sessions and people write. The Help's
Settings topic says so to users.

## How it works

`src/app/core/i18n/` holds it all.

- **The key is the English text.** `tr('Back up now')` in code and
  `{{ 'Back up now' | t }}` in templates give the text in the language shown;
  English needs no dictionary, and a string not translated yet shows in
  English.
- **Placeholders** are `{name}`: `tr('Backed up {time}', { time })`,
  `{{ 'Pull {name}' | t: { name: set.name } }}`. Translations keep every
  placeholder (they may move it).
- **A note after `||`** tells two identical English strings apart when they
  translate differently: `tr('System||theme')` ("Theo hệ thống") beside
  `tr('System')` ("Hệ thống"). The note is never shown.
- **Plurals**: `plural(3, 'session')` is "3 sessions" in English and
  "3 phiên" in Vietnamese; both the singular and the plural are keys.
- **Times and dates**: `relativeTime`, `resetsIn`, `resumesIn` and
  `resetClock` (`shared/util.ts`) speak the language shown; dates use
  `locale()`.
- **The computer** is never "the Mac" in a sentence: it is
  `{computer}` with `computerNoun()` — "Mac", "PC" or "computer" after the
  desktop's system (Vietnamese "máy Mac", "máy PC", "máy tính"):
  `tr('Answer it on the {computer}.', { computer: computerNoun() })`. Its file
  manager is `fileManagerName()` (Finder, File Explorer).
- `tr()` and the `t` pipe read the language signal, so a template, a
  `computed` or an `effect` that uses them follows a switch. A string stored
  once (a constant computed at import) does not: translate where it is
  shown, not where it is defined.
- The dictionaries are JSON in `src/app/i18n/vi/`, one file per area of the
  app, merged by `index.ts`, and loaded only when Vietnamese is shown (its own
  chunk), before the app starts when it is the device's language.

## Writing translatable code

Templates:

```html
<h2>{{ 'Your backups' | t }}</h2>
<button [attr.aria-label]="'Close' | t" [title]="'Close' | t">…</button>
<input [placeholder]="'Search sessions' | t" />
<span
  >{{ 'Backed up from this {computer} {time}' | t: { computer: computer(), time: ago() } }}</span
>
```

- Add `TPipe` (`core/i18n/t.pipe`) to the component's `imports`.
- One sentence is one key. Text with `{{ }}` inside becomes one key with
  placeholders, never pieces glued around the values.
- A sentence with an element in it (a link, `<strong>`, `<mc-time>`): keep
  the element, translate the text on each side as its own key, and word the
  pieces so that each reads well in Vietnamese order; or give the element's
  value as a placeholder when it is plain text (`relativeTime(ms)` instead
  of `<mc-time>`).
- Attributes: `aria-label`, `title`, `placeholder`, `label`, a sheet's
  `title` input — every text a person reads or hears.

Code:

```ts
import { tr } from '../core/i18n/i18n';
this.notices.success(tr('Sent: Claude reads it after its current step.'));
return tr('{name} is being backed up already.', { name });
protected readonly label = computed(() => (this.busy() ? tr('Starting…') : tr('Back up')));
```

- Translate at the point of use; a constant table of labels stays English
  and is translated where it is read: `tr(STATUS[s].label)`.
- Never build a sentence by concatenating translated pieces.
- Errors the server sends are shown as they come (English).
- Server text drawn from a **fixed list** is translated on the client, by
  matching the server's English and falling back to it unchanged when
  nothing matches: activity labels (`activityLabel`), pending titles
  (`pendingTitle`), plan window names (`windowLabel`), budget names and
  notes (`budgetLabel`, `budgetNote`), task classes and effort ids
  (`taskClassLabel`, `effortIdLabel`), the report's estimate note and the
  backup's pruning warning. Each names the Rust function it mirrors; change
  both together. Sentences the server composes from many parts are not
  matched this way: they would need codes and parameters from the server.

`npm run i18n:check` lists keys used but not translated, placeholders that
differ, and keys translated two ways; `--text` also lists template text not
wrapped yet, `--files a,b` limits it to some files.

## Help

The Help center's topics are typed data: English in
`src/app/pages/help/help-topics.ts`, Vietnamese in
`src/app/pages/help/vi/topics-*.ts` by topic id, loaded the first time
Vietnamese Help is shown. A Vietnamese topic has **the same sections in the
same order** as the English one: their ids, links and embeds come from the
English topic (so `#fragments` stay valid), and a topic whose sections do
not line up shows in English. Its `**bold**` keeps the labels as the
Vietnamese interface shows them.

## Adding a language

1. Add it to `LANGS` and `Lang` in `core/i18n/i18n.ts`, and load its
   dictionary in `dictionaryOf`.
2. Copy `src/app/i18n/vi/` to its folder and translate every value.
3. Add its Help next to `pages/help/vi/` and to `help-localized.ts`.
4. `npm run i18n:check` (point it at the new folder).
